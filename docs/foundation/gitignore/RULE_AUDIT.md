## Classification and ownership

Each rule has one primary classification; security implications can also apply to
other categories. Universal means high-confidence local clutter. Profile-specific
means generated or local tool state conditional on selecting that capability.
Repository-local means an Empathy integration exception. Broad/ambiguous means a
name alone cannot establish that every matching path is disposable. Obsolete/duplicate
includes compensation rules that become unnecessary only after their parent exclusion
is removed; it does not assert that they are all redundant in the current root.

Empathy owns the reusable baseline/profile decisions. Named specialist owners retain
their implementations. A consumer owns its project-specific paths and exceptions.
References to capabilities without an existing catalog profile are ownership proposals,
not new profile IDs. **Before live root migration, every proposed relocation must resolve
to a concrete scoped rule or a documented decision to keep that content trackable.**
Private-material protections must have a narrower tested replacement first.
